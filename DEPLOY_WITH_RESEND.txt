MUKUYU SCHOOL PORTAL — DEPLOYMENT AND RESEND SETUP
=================================================

The portal already contains server-side Resend integration for temporary-password emails. Do not paste the PHP onboarding example into this project: it is a React/TypeScript server app, not a PHP app.

IMPORTANT SECURITY
- Do NOT put the real Resend API key in source files, this ZIP, frontend code, screenshots, or GitHub.
- Enter secrets only in your hosting provider's private Environment Variables settings.
- Never share your database connection string or SESSION_SECRET in chat.
- Back up your database before the first production deployment. Deploying code is not a substitute for a database backup.

RECOMMENDED DEPLOYMENT TARGET: VERCEL
This project includes vercel.json, but you still need a Vercel account/project and a persistent PostgreSQL database (for example, Neon). The ZIP alone cannot create those accounts or provision a production database.

1. Upload the ZIP to a private GitHub repository or import/deploy the project using a deployment method that supports this Vite/TanStack Start app. Keep the repository private.
2. In Vercel, open the project -> Settings -> Environment Variables. Add the variables below for Production (and Preview if you want preview deployments to send email).

REQUIRED VARIABLES
- DATABASE_URL = your PostgreSQL/Neon connection string. Use the production database connection string supplied by your database provider. Keep it private.
- SESSION_SECRET = a cryptographically random secret of at least 32 random bytes. Generate one securely on your own device or with your hosting provider's secret generator. Do not use a sample or publish it.
- RESEND_API_KEY = your Resend API key. Prefer a key with Sending Access only.
- EMAIL_FROM = a sender on a domain you own and have verified in Resend, for example: Mukuyu School <no-reply@your-verified-domain.example>
  Replace the example address with a real sender on your verified domain. Do not use the .example address literally.

3. In Resend -> Domains, add a domain you own and follow the DNS instructions from Resend at your domain registrar. You cannot verify a domain you do not control. The onboarding sender onboarding@resend.dev is for limited testing; production email requires an appropriate verified sender/domain.
4. Make sure Vercel has the correct DATABASE_URL and secrets configured before deploying. Redeploy after changing environment variables.
5. Run the project's database migration command in the deployment environment as required by your hosting workflow. The package's build script includes db:migrate; confirm the production database is backed up and migrations complete successfully before using the portal.
6. After deployment, test sign-in and password-reset emails for each role. Confirm emails arrive, check Resend logs, and test that existing student records and marks remain present.
7. Configure automatic database backups / point-in-time recovery with your database provider and download the portal's own backups regularly.

CURRENT LIMITATION
This ZIP has not been fully validated with a successful production build in this environment. Hosting, database provisioning, environment variables, DNS verification, and production smoke tests still need to be completed. Do not treat it as production-ready until those checks pass.
